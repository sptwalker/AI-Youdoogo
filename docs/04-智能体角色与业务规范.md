# 04-智能体角色与业务规范

> 修订说明（2026-07-11）：**首个落地部门智能体为平台运营部（阶段2实现）**，其余部门智能体按里程碑计划（docs/06）后续阶段逐步落地。模型选型以 DeepSeek 为主力（deepseek-chat 日常 / deepseek-reasoner 会商推理），统一降级链 → Qwen → GLM，详见 docs/09-模型网关设计。

## 1. 智能体通用规则

- 所有AI智能体严格遵循**角色专属职责**，不跨部门越权操作
- 所有输出必须**数据可溯源**，禁止幻觉式无依据输出
- 所有自动执行任务、生成内容，均留存完整日志
- 复杂问题优先调用知识库、历史数据、行业数据辅助分析
- **红线：AI仅有建议权、分析权、辅助执行权；涉及业务调整、资金、项目、人事的决议必须真人确认生效**

## 2. 通用智能体能力

所有部门Agent统一具备：日常数据监控、异常识别、报告生成、任务接收、任务反馈、提案生成、知识检索能力。

## 3. 各部门智能体详细职责

### 3.1 平台运营部AI智能体（首个落地，阶段2）

- 角色：运营AI总监 + 用户数据分析Agent
- 日常工作：用户活跃监控、功能使用数据分析、运营数据汇总、用户反馈整理、活动复盘
- 输出产物：运营日报、月度运营报告、运营优化提案、用户体验优化建议
- 数据来源：飞书 + 内外部业务数据平台API + Excel/文档人工上传（详见 docs/11）

### 3.2 销售营销部AI智能体（后续阶段）

- 角色：销售AI总监 + 渠道数据分析Agent + 营销效果Agent
- 日常工作：每日销量监控、渠道数据统计、营销活动效果分析、客户数据复盘、销量趋势预测
- 输出产物：销售日报/周报、渠道优化提案、营销调整提案、销量风险预警

### 3.3 游戏研发部AI智能体（后续阶段）

- 角色：研发AI总监 + 进度管控Agent + 质量分析Agent
- 日常工作：迭代进度监控、bug数据统计、研发人力负载分析、项目风险排查、版本复盘
- 输出产物：研发周报、进度风险预警、研发流程优化提案、质量整改提案

### 3.4 基础产品部AI智能体（后续阶段）

- 角色：产品AI总监 + 产能供应链Agent
- 日常工作：产品产能监控、物料库存预警、产品良率分析、产品迭代进度跟踪
- 输出产物：产品生产报告、库存风险预警、产品优化提案

### 3.5 职能管理AI智能体（后续阶段）

- 角色：财务人事AI Agent、行政法务AI Agent
- 日常工作：预算执行监控、人力数据统计、合同合规初审、行政事务复盘
- 输出产物：财务月报、人力分析报告、合规风险提示

### 3.6 决策层AI专家智能体（后续阶段）

- 角色：CEO/CPO/COO/CMO/CFO对应AI专家
- 工作场景：仅参与高层决策会议
- 核心能力：跨部门数据整合、方案利弊推演、风险评估、历史案例对比、参考投票

## 4. 角色注册表键名约定

角色到模型的映射统一在 `app/llm/roles.py` 注册，键名固定如下（降级链统一：主力模型 → qwen → glm）：

| 键名 | 角色 | 主力模型 | 降级链 |
|---|---|---|---|
| `ops_director` | 运营AI总监 | deepseek-chat | → qwen → glm |
| `data_analyst` | 数据分析Agent | deepseek-chat | → qwen → glm |
| `meeting_expert` | 会商AI专家 | deepseek-reasoner | → qwen → glm |
| `default` | 兜底（未注册角色统一走此项） | deepseek-chat | → qwen → glm |

约定：

- 新增部门智能体时先在此表登记键名，再在 `app/llm/roles.py` 注册，两处保持一致
- 模型密钥只走环境变量（`.env` → `app/core/config.py`），禁止硬编码；用量首版记日志不入库（详见 docs/09）

> **实施说明（阶段2~5）**：角色分两层——(1) `app/llm/roles.py` 的 **LLM 角色键**（上表，主模型+降级链）；(2) `agent_role` **数据库表**（业务角色配置：prompt_template/duty/permission_scope/model_role），新增部门智能体=建一行（`POST /agents/roles`，零新代码即被调度中枢通用驱动）。`agent_role.model_role` 为粗档位（`daily`/`reasoning`），映射到 LLM 角色键（`daily→default`、`reasoning→meeting_expert`）。已随迁移种子写入：**运营AI总监**（daily）、**会商AI专家**（reasoning）。
>
> 智能体执行统一走 `app/agents/base.run_agent`（加载角色→调模型→写 `agent_task_record` 留痕，成功/失败都留痕）。已落地 task_type：`daily_report`（运营日报）、`anomaly_alert`（指标异常告警）、`proposal`（运营提案）、`proposal_research`（提案会前预研）、`proposal_execution`（提案转任务卡执行）。反馈评分→提示词优化见 docs/06 阶段5。

## 5. 任务卡协同规范

- 高优先级任务自动插队执行，低优先级任务后台排队
- 跨部门任务由调度中枢统一拆解分发，禁止Agent私自跨部门指派
- 任务超时自动告警、自动推送负责人
- 任务完成必须返回标准化结果，方可闭环归档
