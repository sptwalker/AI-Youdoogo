# 02-系统总体架构设计文档

> 修订说明：本文档自原前置开发文档"02-系统总体架构设计文档"提取，并按 2026-07-11 技术选型修订决策更新（技术栈唯一事实源见项目根目录 CLAUDE.md）。

## 1. 架构设计原则

- **分层解耦**：各层级职责单一、边界清晰，低耦合高内聚
- **模块化可扩展**：支持场景迭代、部门新增、模型替换、系统接入
- **数据驱动**：所有AI输出、决策建议均依托真实业务数据，杜绝纯空想输出
- **安全可控**：全链路权限管控、操作留痕、人工兜底
- **轻量化落地**：适配初创团队，避免过度设计，MVP快速验证价值

## 2. 整体七层技术架构

基础设施层 → 数据存储层 → 安全审计层 → 能力中台层 → 智能体编排层 → 业务服务层 → 前端应用层

### 2.1 基础设施层

系统底层运行支撑，包含Docker容器化环境、服务器资源、网络配置、日志监控、定时任务服务，保障系统7×24小时稳定运行。

### 2.2 数据存储层

统一多类型数据存储，一站式解决企业所有数据存储需求：

- PostgreSQL 16：核心结构化业务数据、用户权限、任务、提案、会议数据
- pgvector（内置于同一 PostgreSQL 实例）：文本向量存储、语义检索、知识库匹配
- TimescaleDB（内置于同一 PostgreSQL 实例）：业务时序数据、每日运营数据、产能数据、销量数据
- Redis：预算计数、熔断与短期共享状态；**不作为 durable 工作流/任务队列真相源**
- MinIO：文档、报表、PPT、附件等非结构化文件存储

> 部署说明：PostgreSQL / TimescaleDB / pgvector 采用 `timescale/timescaledb-ha:pg16` **单镜像**部署（镜像内置 TimescaleDB 与 pgvector 扩展），不再分开部署三套数据库服务。

### 2.3 安全审计层（全链路穿透）

贯穿系统所有层级，实现全方位安全管控：权限校验、数据脱敏、操作审计、接口风控、AI输出内容审核、越权拦截、日志留存。

权限首版简化落地：登录 + 3角色（admin / executive / member），表结构预留四级RBAC扩展位。

### 2.4 能力中台层（公共底座）

全系统通用能力封装，所有智能体共享调用，避免重复开发：

- 大模型网关：复用 Bottleneck-Hunter 多模型网关方案（`app/llm/`，langchain-core + langchain-openai），统一封装 DeepSeek 主力（deepseek-chat 日常 / deepseek-reasoner 会商推理）及降级链 → Qwen（通义/DashScope）→ GLM（智谱），Claude 后期可选；含模型工厂、failover、健康检查与角色模型映射，密钥走环境变量，首版用量记日志不入库。详见 docs/09-模型网关设计
- 企业知识库中台：文档解析、分块、向量化、检索、溯源
- 通用工具库：数据分析、报表生成、文档制作、消息推送、数据查询、舆情检索
- 告警通知中台：系统异常、业务异常、任务超时、会议提醒

### 2.5 智能体编排层（系统核心）

**编排引擎：PostgreSQL durable runtime + 自研 DAG adapter**（2026-07-20）：

- 普通单任务：`task_flow.py` + `scheduler.py` 保持任务卡状态机（created→dispatched→executing→reported→accepted/rejected）。
- 复合任务：`WorkflowRun/WorkflowStep` 是运行态真相源，`TaskCard` 只作为 UI 与真人验收镜像；父流程独立持久化 queued/running/waiting_human/succeeded/failed/cancelled。
- 可靠执行：业务状态与 `OutboxEvent` 同事务提交；后台 worker 用 version/CAS、租约与 attempt 抢占步骤，HTTP/SSE 不同步执行完整 DAG。
- 崩溃恢复：步骤忙碌事件 defer 到步骤租约结束；Worker 周期扫描过期 `running` 步骤并用稳定 dedupe key 补发，原事件丢失也能恢复。
- 幂等技能：`ToolDispatcher` 统一执行强类型 `SkillRequest`；文件交付、协作请求先写 `ToolExecution`，重复事件复用既有结果。
- 追踪：workflow/step/attempt/trace 贯穿工作流事件、AgentTaskRecord、LLM log 与工具执行。
- 模块边界：工作流按 repository/state/projection/recovery 拆分，Worker 按 loop/event handler/step executor 拆分，技能按 registry/legacy adapters/dispatcher 拆分；旧入口只作 facade。
- LangGraph 边界：未来只替换 `WorkflowEngine`/planner adapter，继续复用现有数据库状态、outbox、ToolExecution 和真人停点。
- 部门智能体集群：角色配置化（`agent_role` 表），新增部门智能体=建一行角色（prompt_template + model_role），零新代码即被调度中枢通用驱动。首个落地：平台运营部（运营AI总监）
- 会商智能体：决策层 AI 专家（会商AI专家，reasoning 档位），参与提案会前预研；会议讨论、真人/AI 投票、纪要、决议确认与转任务已实现（`meeting_*`，迁移 009）。

### 2.6 业务服务层

封装所有业务接口与逻辑：用户权限、任务卡管理、提案管理、会议管理、数据接入（飞书 / 内外部业务数据平台API / Excel与文档人工上传，飞书集成为自研异步 httpx 客户端 `app/integrations/feishu/`，详见 docs/10-飞书集成设计、docs/11-数据接入设计）、报表服务、系统配置服务。桌面对话流、飞书 OAuth 配置/单次票据、会议 AI 动作均与各自 CRUD/编排 facade 分离。

### 2.7 前端应用层

企业管理后台（React + Ant Design Pro，**阶段2才初始化**），包含数据总览看板、任务协同看板、提案管理页面、会议管理页面、知识库页面、系统配置页面、权限管理页面。Dashboard 与 OrgAdmin 页面仅作为路由容器，独立展示区、数据 Hook、组织树和编辑器位于组件层。

## 3. 核心业务流转架构

数据接入 & 治理 → 智能体自动监控分析 → 生成提案/任务 → 中枢调度流转 → 决策层会商评审 → 决议拆解执行 → 全流程沉淀知识库 → 系统复盘自优化

## 4. 技术栈整体清单

| 层 | 选型 |
|---|---|
| 语言/工具链 | Python 3.12 + **uv**（`uv sync` / `uv run`） |
| Web框架 | FastAPI + Uvicorn |
| ORM | SQLAlchemy 2.0 **async** + asyncpg + Alembic |
| 校验/配置 | Pydantic v2 + pydantic-settings |
| 智能体框架 | 普通任务 `task_flow`；复合任务 PostgreSQL durable runtime + `WorkflowEngine` adapter；LangGraph 后续可插拔 |
| 数据库 | PostgreSQL 16（`timescale/timescaledb-ha:pg16` 单镜像，内置 TimescaleDB + pgvector） |
| 缓存/共享状态 | Redis（durable 队列使用 PostgreSQL outbox） |
| 文件存储 | MinIO |
| 大模型 | DeepSeek 主力（deepseek-chat / deepseek-reasoner），降级链 → Qwen → GLM，Claude 后期可选；多模型网关 `app/llm/` |
| 飞书集成 | 自研异步 httpx 客户端 `app/integrations/feishu/`（不用 lark-oapi SDK） |
| 前端 | React + Ant Design Pro（**阶段2才初始化**） |
| 代码规范 | Ruff + Mypy + Pytest |
| 部署 | Docker Compose |
