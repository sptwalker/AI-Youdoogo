RULEvisible_knowledge_base_ids() 的真实分支

机密部门库

容易误读的点实际规则接手动作
AI 与真人范围相同？不同。AI 注入只看公司库 + 本部门库 + 本人私库，不看其他部门普通库改可见性时同时跑真人与 Agent 两组测试
grant 能给审批权？不能。grant 只授 read / write / admin 的资源访问，不授业务生效权角色判断仍走 require_roles / domain actor
无权资源返回 403？行级策略可 conceal，统一表现为“资源不存在”，避免泄漏存在性列表过滤与详情守卫必须使用同一 policy

长任务真相源放哪：为什么不是内存，也不是 Redis？

候选

选择

MECH一次可靠推进的完整顺序

1 写业务状态Run / Step / Task projection
→
2 enqueue Outbox同一 DB 事务，dedupe_key 唯一
→

→
4 complete / failowner 条件更新；失败延迟再试
候选故障时丢什么为什么不做真相源
内存进程重启后队列、执行位置、等待人状态全部丢失无法回答“任务到底做到哪”
Redis可持久化但与业务数据库事务分离容易出现业务写成功、事件没入队或反之；更适合缓存 / 协调
PostgreSQL进程可死，状态仍在；过期 lease 可恢复选中：事务、约束、审计和条件更新在一个真相源内
当前实现 Outbox 有持久化、租约、重试和恢复，但 handler 仍在同一进程消费；不能称作跨服务 Event Bus。

COST代价

  • 数据库多出轮询、索引、租约续期和历史清理压力。
  • 必须监控 pending 数、最老 available_at、失败终态和 lease 过期率。
  • 物理拆分后仍要补 Relay / Inbox / DLQ 与跨服务重放。
禁止：把 Redis 队列当唯一进度；把外部调用放在未提交事务里长时间占连接；成功写业务后再“尽力发消息”。

DECISION 04 · RETRY

重试怎么不重复副作用：具体靠哪三道栅栏？

07
候选
超时就再调一次全局锁幂等 + lease + CAS
选择
重复投递允许发生，但同一业务效果只允许生效一次
幂等键

Outbox dedupe_key 唯一；冲突时返回既有事件。副作用键建议 execution:step:tool-index。

租约

lease_owner + lease_until；只有当前 owner 可续租、complete、fail。Worker 死亡后过期可重领。

CAS 条件更新

用 version == expected 和 rowcount == 1 防止旧 Worker 覆盖新状态。

现场系统判定处理是否消耗 retry
重复点击 / 重复投递相同 dedupe / idempotency key返回已存在结果否
另一个 Worker 正在跑有效 lease，claim 得到 busyOutbox defer()；attempts 减回去否
Worker 崩溃lease 过期新 Worker reclaim；attempt + 1是
旧 Worker 晚到回执owner / attempt / version 不匹配finalize 被判 stale，拒绝写入不再覆盖新状态
真实外部失败异常且当前 owner 有效fail → pending 延迟重试或 failed 终态是

COST代价

  • 每个副作用都要定义稳定业务键，不能用随机 request_id 冒充。
  • lease 秒数太短会重复执行，太长会拖慢恢复；需 heartbeat。
  • 外部系统若不支持幂等，必须加本地执行记录和结果查询。
接手规则：看到 retry 先问“这个调用是否幂等”；答不出来就不能自动重试。

DECISION 14 · MIGRATION

怎么拆才不把风险一次性兑现：两条纪律 + 六步回退路线

17

纪律 1“拆出去”先指所有权与契约独立

成功标准可验证含义
独立所有权数据只有一个写真源；其他服务只持 ID / 投影；无共享 ORM / 账号 / 跨库 Join
独立发布契约兼容时 Provider 可先发；消费者不需要同一窗口升级
独立失败平台超时 / 熔断后业务有明确降级、暂停或 Local 回退路径
不是成功标准：仓库数量、Deployment 数、把 HTTP 调通。首日四套部署最可能得到分布式单体。

纪律 2运行中实例不跨引擎迁移

旧 Workflow 在 Local Runtime drain 到终态；只有新创建且命中特性路由的流程进入 Remote Runtime。回滚时停止新流量，不把半程流程搬回来。

PLAYBOOKPort → Local → Remote → 灰度 → 默认远程 → 删除

步骤完成定义失败时回退
1 Port业务用例只依赖纯契约；无 ORM / SDK 对象小提交回退，不改运行拓扑
2 Local Adapter包装当前实现；全部旧测试不变继续使用旧实现
3 Remote Adapter契约测试、Internal JWT、timeout / error mapping 完成开关保持 Local
4 灰度按 use_case / knowledge_base / workflow_type / percentage；对账达标路由切回 Local，追平远程数据
5 默认远程完整稳定周期、故障演练、回滚演练通过Local 保留明确截止窗口
6 删除兼容层旧流量 / 实例 / 回放窗口清空，备份可恢复删除前保留版本制品；之后才是不可逆
代价：过渡期双 Adapter、特性路由、对账、投影追平和消费者契约都要维护；换来每一步可验证、可观察、可回退。
迁移纪律：能不用双写就不用；优先旧真源 Outbox 增量同步 + 批量回填 + 切换写真源，禁止两个服务同时被认为是真源。
