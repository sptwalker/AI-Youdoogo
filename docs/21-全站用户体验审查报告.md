# 全站用户体验审查报告

> 审查时间:2026-07-27 · 审查方式:分 4 组(工作台+聊天 / 业务页面 / 管理配置 / 登录+全局)按真实用户视角只读审查
> 覆盖:17 个页面 + 主布局 + 全局请求/鉴权/主题
> 分级:P0 阻断/数据风险 · P1 明显影响 · P2 体验缺口 · P3 打磨

---

## 一、总体结论

系统基础扎实:统一 `ApiError` + 401 集中处理、zh-CN、飞书 OAuth 状态机、路由错误边界、密钥全链路脱敏、危险动作多数有 `Popconfirm`、异步请求普遍防竞态。**未发现前端安全漏洞或数据丢失级 P0**,唯一 P0 是一类「危险操作缺二次确认」。

最突出的系统性问题有三:
1. **同一「群聊/协作」概念存在三套割裂 UI**(桌面助理 / 工作桌面内嵌 GroupChat / `/discussion` 的 AdvisorChannel),能力、措辞、颜色、时间显示都不一致。
2. **列表页普遍关掉搜索/筛选/排序,分页多为假分页或不分页**,数据一多就难用(审计日志尤甚——合规页只能看最近 100 条)。
3. **加载/错误/空三态不齐、失败静默**,多处 `.catch(()=>{})` 或 `success:true` 恒真,用户看到空页会误判「没数据」。

## 三、P0 — 阻断 / 数据风险

### P0-1 危险操作全部缺二次确认
- **位置**:`Tasks.tsx:85-105`(驳回/终止)、`Meetings.tsx:141-149`(结束会议)、`Users.tsx:50-58`(停用 Switch)
- **用户视角**:任务终止/驳回、会议结束、用户停用都是不可逆状态流转,却单击即生效。手滑即中,无法撤销。同仓库知识库删除已用 `Popconfirm`、提案驳回强制填意见,唯独这些裸奔,一致性也差。
- **建议**:带 `danger` 的流转按钮、结束会议、停用开关统一包 `Popconfirm`(复用现成组件,最小改动)。

## 四、P1 — 明显影响

### 聊天/协作
- **P1-1 群聊发送无乐观回显,输入框等 AI 全部流式结束才清空** — `useMessageComposer.ts:77-89`。发送后自己的消息不立刻出现、输入框不清空、按钮一直转,直到 AI 说完。桌面助理 `useDesktopChat.ts:151-155` 已做对,应对齐。
- **P1-2 新消息/流式增量把已上滚用户强制拽回底部** — `MessageList.tsx:16-19`、`useDesktopChat.ts:75-78`。应仅在贴近底部时自动滚,否则显示「回到底部/N 条新消息」。
- **P1-3 发送失败缺明确反馈与重试** — `useStreamingSend.ts:28-30`、`useDesktopChat.ts:189-193`。失败时占位气泡消失但无 toast、无重试,群聊连乐观气泡都没有,消息「凭空消失」。
- **P1-4 群聊完全无时间显示** — `MessageList.tsx:51-88`。`Message.create_time` 有数据未渲染;复用桌面助理 `shouldShowTimeSeparator`。
- **P1-5 三套群聊体验割裂、能力不对等** — `/discussion` 的 `AdvisorChannel`(单行输入、无附件/表情/截图/搜索/引用/置顶)vs 工作桌面 `GroupChat`(全都有)。建议统一到同一套列表 + Composer。

### 业务页面
- **P1-6 提案无法查看正文,详情只给评审记录** — `Proposals.tsx:49-53,172-184`。评审人看不到方案就要评审,流程不闭环;`getProposal` 已返回 `proposal` 却被丢弃。
- **P1-7 投票统计把原始 JSON 直出给用户** — `Meetings.tsx:246`,渲染成 `真人 {"approve":2}`。应转中文「赞成 X/反对 Y」。
- **P1-8 表决对象靠手打字符串精确匹配** — `Meetings.tsx:210-248`。看统计要一字不差重输 subject,差空格就查不到。应提供已有表决对象下拉。
- **P1-9 智能体评分可无限重复提交且不回显** — `Agents.tsx:65-75`。`Rate` 未绑 value,拖一次发一次,刷新清零。应绑定已有评分并提交后只读。
- **P1-10 新建会议用浏览器原生 `prompt()`** — `Meetings.tsx:118-122`。样式割裂、无校验。改 `ModalForm`。

### 管理配置
- **P1-11 审计日志假分页,只能看最近 100 条** — `AuditLog.tsx:29-33`、`admin.ts:27`。合规审计页翻到第 5 页到底,更早永远看不到。接服务端分页或至少提 limit 并明示。
- **P1-12 审计无法查看变更 detail,无操作者/时间范围筛选** — `AuditLog.tsx:6-19`。后端已返回 `detail`、支持 `actor_id`,前端全没用。「看得见发生过,查不出改了啥」。
- **P1-13 无法为已有用户重置密码** — `Users.tsx:62-109`。密码只在新建时设,忘密码/轮换无任何手段。
- **P1-14 用户停用开关无二次确认**(并入 P0-1)。

### 登录/全局
- **P1-15 会话过期跳回登录页无任何解释** — `client.ts:84-87`、`RequireAuth.tsx:8-10`。401 跳登录时刻意跳过 toast,用户被整页甩回登录页,以为系统坏了。建议带 `?expired=1` 让登录页提示「登录已过期」。
- **P1-16 401 用 `window.location.href` 整页硬跳转** — `client.ts:60`。白屏重载,丢失 SPA 体验。优先走 router 编程式导航。

## 五、P2 — 体验缺口

### 聊天/协作
- **P2-1** 任何对话都不能撤回/编辑/删除消息(三套均无)。
- **P2-2** @提及不友好:靠独立下拉框,不能在输入框内打「@」触发 — `MessageComposer.tsx:122-136`。
- **P2-3** 群聊 @AI 数量静默截断(选 5 个只生效 3 个)— `MessageComposer.tsx:123-136` 无 `maxCount`,`model.ts:129-131` `.slice(0,3)`。
- **P2-4** 无「加载更多历史」/分页 — `discussion.ts:123-125`、`getDesktopChat` 均无分页。
- **P2-5** 无草稿保存,切频道/刷新即丢 — 各 composer `useState` + `key={active.id}` 重挂。
- **P2-6** 群聊自己的消息无视觉区分(全部左对齐白底)— `MessageList.tsx:59-73`。
- **P2-7** 长文本/长 URL 撑破气泡 — 气泡缺 `overflowWrap:'anywhere'`。
- **P2-8** 消息加载/错误三态缺失,切频道闪空 — `useDiscussionFeed.ts:142-158`。
- **P2-9** 键盘可访问性缺失(大量 `<a>`/`<div onClick>` 无 role/tabIndex/aria)。
- **P2-10** 精确时间/操作只在 hover 出现,触屏不可达 — `AssistantChatCard.tsx:270-297`。
- **P2-11** 图片预览无虚拟化 + 后加载顶乱滚动定位 — `MessageList.tsx:90-142`、`InlineImage`。

### 业务页面
- **P2-12** 任务创建后无法补指派/编辑,漏选智能体就永远跑不了 — `Tasks.tsx:64-84,150-168`。
- **P2-13** 任务驳回/终止不记录原因(`transitionTask` 的 `note` 从未使用)— `Tasks.tsx:94-99`。
- **P2-14** 任务类型自由文本易脏数据,列表显原始值(Agents 已有 `TASK_LABEL` 可复用)— `Tasks.tsx:49,151`。
- **P2-15** 任务指派智能体展示原始 UUID — `Tasks.tsx:124`(并入 X5)。
- **P2-16** 会议「发言」与「AI 专家」共用同一输入框,易误操作 — `Meetings.tsx:161-204`。
- **P2-17** 列表加载失败无重试入口(`success:true` 恒真)。
- **P2-18** 新建会议按钮不受 `canManage` 限制,造出「建了却开不了」的会 — `Meetings.tsx:117-123`。

### 管理配置
- **P2-19** 组织架构用原生 `prompt()` 改名/加部门(无 trim/查重/长度)— `OrgAdmin.tsx:81,113`。
- **P2-20** 多列表页无搜索/筛选(Users/KnowledgeBases/DataSources/SemanticTerms)。
- **P2-21** SystemConfig/AiProviders/SemanticTerms 缺加载态,失败静默(`.then(setX)` 无 catch)。
- **P2-22** SystemConfig JSON 型字段无格式校验,非法 JSON 也能存,运行时才炸 — `SystemConfig.tsx:146-148`。
- **P2-23** 「AI 大模型」可能出现两张同名卡片,指引与内容矛盾 — `SystemConfig.tsx:166` vs `25/245-246`。
- **P2-24** 知识库授权列表只显 ID 前 8 位(已加载 users/depts 未用)— `KnowledgeBases.tsx:175`(并入 X5)。
- **P2-25** 卡片内联操作(测试/设主用)点击后无 loading,慢网易重复点 — `AiProviders.tsx:104-110` 等。
- **P2-26** 数据接口无「单条测试连通/测试密钥」— `DataSourceRegistry.tsx`。

### 登录/全局
- **P2-27** 首屏/切页白屏,无加载指示 — `index.html:9-11`、`router.tsx` 所有 lazy 路由。
- **P2-28** 登录/系统主色不一致,缺统一品牌主题 — `main.tsx:21` `ConfigProvider` 只设 locale(并入 X6)。
- **P2-29** 登录失败提示是右上角 toast 而非表单内联(飞书错误却用 Alert,不一致)— `Login.tsx:74-80`。
- **P2-30** 无「记住登录」,token 恒写 localStorage(公用电脑隐患)— `Login.tsx:76`、`client.ts:5`。

## 七、做得好的地方(保持)

- 桌面助理流式回写 + 乐观发送 + 失败回填设计完整,是三套聊天里最好的,应作为统一基准。
- realtime + 轮询降级、未读增量、附件 blob 的 AbortController/revokeObjectURL 清理得当。
- 密钥体验全链路脱敏:SystemConfig 只显已配置/未配置且不回显、AiProviders 显末 4 位、DataSource 只存 .env 变量名。
- 权限加载失败不静默降级,给重试+退出;路由错误边界 + 兜底 unhandledrejection 完整。
- 新建 AI 卡片后自动测连通并按结果反馈;`useEventNaming`/`OrgAdmin` 用 requestId 防竞态。
