# 物理拆分工程底座配置

本文记录物理拆分前置能力的最小配置和启用边界。当前交付只建立可测试的技术机制，**没有改变生产拓扑**，也没有把业务 Context、HTTP 路由、现有 Outbox Worker 或用户认证接到远程服务。

## 1. 内部服务身份

`app/platform/service_identity/` 提供独立 RS256 短期 JWT。它不读取、不复用现有用户 `JWT_SECRET`，也不会在进程内生成密钥。

最小配置：

```dotenv
INTERNAL_JWT_ENABLED=false
INTERNAL_JWT_ISSUER=youdoo-internal
INTERNAL_JWT_AUDIENCE=knowledge-service
INTERNAL_JWT_SERVICE_ID=business-api
INTERNAL_JWT_PRIVATE_KEY=
INTERNAL_JWT_PUBLIC_KEY=
INTERNAL_JWT_TTL_SECONDS=300
```

- 默认必须保持 `INTERNAL_JWT_ENABLED=false`，直到 Remote Adapter、接收端验签和密钥轮换演练完成。
- 私钥只注入调用方；接收服务只注入公钥。真实 PEM 应由部署平台的 Secret/Vault/KMS 注入，禁止提交到仓库。
- Token 使用标准 `iss`、`aud`、`iat`、`exp`、`jti`，并携带 `service_id`、`actor`、空格分隔的 `scope`；最长有效期固定为 300 秒。
- `actor` 表示被服务调用代表的真人或系统主体；接收端仍须按操作校验所需 scope，不得只验证签名。
- 当前模块只支持单把 RS256 公私钥；生产启用前还需增加 `kid`/JWKS 或等价的双钥轮换窗口。

## 2. MinIO TLS、presign 与最小权限

旧 `put_object` / `get_object_bytes` API 保持不变。新增配置：

```dotenv
MINIO_SECURE=false
MINIO_ALLOWED_BUCKETS=
MINIO_ALLOWED_PREFIXES=
MINIO_PRESIGN_EXPIRE_SECONDS=900
```

- `MINIO_SECURE=false` 保留本地兼容行为；生产 MinIO 配置证书后改为 `true`。
- bucket allowlist 为空时，仅允许 `MINIO_BUCKET`。prefix allowlist 为空时，为兼容旧调用，允许该 bucket 内现有全部对象键。
- prefix 使用逗号分隔的路径段，例如 `deliverables,knowledge/private`；`deliverables` 不会授权 `deliverables-private`。
- `presign_get_object` / `presign_put_object` 生成 1 秒到 7 天的临时 URL，默认 900 秒。应用侧 allowlist 只是第二道校验，不能替代 MinIO 服务账号的 bucket/prefix Policy。

启用生产 TLS 时还需同步调整健康检查协议、证书信任链、外部 presign 域名和必要的 CORS；这些运行环境变更不在当前代码交付中。

## 3. 可靠事件契约

`app/platform/event_transport/` 当前只包含：

- `EventEnvelope`：事件 ID、类型、schema 版本、生产者、时间、关联/因果 ID、JSON payload；
- `EventPublisher`：未来 Relay、HTTP 或 Broker Adapter 的发布 Port；
- `EventInbox`：按 `consumer_id + event_id` 认领、租约、完成与失败释放语义；
- `DeliveryFailure`、`DeadLetterStore`、`ReplayRequest`、`EventReplayer`：失败证据、DLQ 和审计重放语义；
- 内存 Publisher、Inbox、DLQ、Replayer：仅用于快速测试，没有持久性，未在 Bootstrap 装配。

重放保留原始 `event_id`。真正接入时，Inbox 的完成记录必须与消费者业务副作用在同一事务提交；否则只能做到消息去重，不能保证业务效果幂等。

## 4. 生产启用前仍需完成

1. 为每个服务建立独立部署身份、Secret 管理、`kid`/JWKS 双钥轮换、时钟同步、scope 清单和密钥泄露撤销流程。
2. 配置 MinIO TLS 证书与信任链、非管理员服务账号、服务端 bucket/prefix Policy、presign 域名/CORS、对象审计和生命周期。
3. 决定 HTTP Relay、NATS 或现有 MQ；实现持久化 Outbox Relay、与业务事务绑定的 Inbox、DLQ 存储、受权重放工具、保留期和积压告警。
4. 完成独立数据库账号/迁移、CCE 容量与故障余量、独立发布回滚模板、OpenTelemetry、SLO 以及重复/乱序/分区/重放演练。
5. 上述门禁未完成前，保持 Local Adapter、当前 Outbox 运行路径和单体部署，不启用远程事件消费者。
