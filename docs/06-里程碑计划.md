# 06-分阶段开发里程碑计划（压缩版 14~16 周）

> 修订日期：2026-07-11。本版替代原 22 周计划，按"单人开发者 + Claude Code"模式压缩为 **14~16 周**。
> 技术栈以 `CLAUDE.md` 为唯一事实源：Python 3.12 + uv、FastAPI、SQLAlchemy 2.0 async、PostgreSQL 16（timescale/timescaledb-ha:pg16 单镜像，内置 TimescaleDB + pgvector）、DeepSeek 主力（降级链 → Qwen → GLM）、LangGraph 1.x（阶段 3 才引入）、React + Ant Design Pro（阶段 2 才初始化）。

## 总体节奏

| 阶段 | 名称 | 工期 | 累计 |
|---|---|---|---|
| 0 | 基础框架 | 1~1.5 周 | 1.5 周 |
| 1 | 权限 + 知识库 MVP | 2 周 | 3.5 周 |
| 2 | 平台运营部智能体闭环 | 3~4 周 | 7.5 周 |
| 3 | 任务卡 + 调度中枢 | 3 周 | 10.5 周 |
| 4 | 决策会商 | 2~3 周 | 13.5 周 |
| 5 | 自进化 + 应急 | 2 周 | 15.5 周 |
| 6 | 服务器迁移部署 | 1 周 | 14~16 周 |

**纪律：每个阶段结束时必须交付一个可独立使用、对管理层有真实价值的东西**，而不是"等全部做完才能用"。首批用户为管理层 3~10 人；首个落地部门智能体为平台运营部。

**关键偏差（相对原计划）**：

1. **智能体编排引擎：LangGraph 1.x → 先自研状态机**（阶段3决策，2026-07-12）。原计划"阶段3 前置 3 天 LangGraph POC"，实际采纳其兜底方案（POC 不过退自研状态机）直接自研，未安装 LangGraph。理由：任务卡流转的编排复杂度用轻量状态机（`task_flow`）即可覆盖，零新依赖、可单测；确有多分支/并行/长流程编排需求时再引入 LangGraph 并补 POC。
2. **阶段4 拆分为两半场**：先交付"提案闭环"（提案卡全生命周期 + AI 会前预研 + 决议转任务卡，红线=真人确认），**会议/投票/纪要（meeting_info/discuss/vote/resolution）后置**为阶段4下半场。理由：提案闭环已能支撑"AI 预研 + 真人决策 + 落地任务"的核心决策价值；完整会议编排更依赖真实使用场景打磨。
3. **Embedding 单 provider 先行**：阶段1 采用通义 text-embedding-v3（1024 维）单一 provider，**bge-m3 的 A/B 选型后置**（需真实公司文档对比检索质量后再定，且需额外部署端点）。
4. **业务时序表提前但降级**：阶段2 即落地 `ops_daily_metric`（普通表），**TimescaleDB hypertable 优化后置阶段4**（届时主键需含 `stat_date`）。
5. **数据库表清单增补**：新增 `llm_call_log`（阶段1）、`ops_daily_metric`（阶段2）、`agent_feedback`（阶段5）三表，已同步进 docs/03；迁移链现为 `001_baseline` → `008_agent_feedback`。

**未做/待办（无 Docker 期间不阻塞主线）**：四级 RBAC 扩展（按项目规则「预留扩展位、按需再建」，非阶段1~5 必做）；embedding A/B **最终选型**（客户端已配置化，可经 .env 换 bge-m3，待其端点 + 真实语料对比检索质量后定型）。

**健壮性处理进展（上生产前）**：
- ✅ R2 列表防 OOM：任务卡/提案/会议/知识库文档/留痕列表均加默认上限（limit 参数，默认 100 / 上限 500），不改响应契约。
- ⏸ R1 LLM 调用同步阻塞（日报/问答/预研等 5s+）：现阶段用户为管理层 3~10 人、低并发，同步等待属可接受 UX，**暂不引入异步**；待并发上升再做**任务队列（Redis/RQ）+ 任务状态轮询**的完整异步层（避免 fire-and-forget 半成品引入会话泄漏/丢任务）。届时 LLM 触发类接口改为返回任务句柄 + 前端轮询。

## 阶段0：基础框架（1~1.5 周）

核心目标：打好工程地基——文档体系、脚手架、容器环境、迁移体系，并完成两块"移植即得"的能力：多模型网关（复用 Bottleneck-Hunter 的 llm_clients 方案，删除每用户密钥仓、密钥改走环境变量、首版用量记日志不入库）与飞书异步客户端（复用 feishu_project_manager 的 httpx 客户端，不用 lark-oapi SDK）。

交付物：

- docs 文档体系 11 篇（01~08 + 新增 09 模型网关设计 / 10 飞书集成设计 / 11 数据接入设计）+ CLAUDE.md
- FastAPI 项目脚手架（app/api、core、models、schemas、services、llm/、integrations/feishu/、utils）
- docker compose：PG（timescaledb-ha:pg16）/ Redis / MinIO 三容器
- Alembic 迁移体系（可 upgrade/downgrade 往返）
- 模型网关移植完成（DeepSeek 主力，降级链 Qwen → GLM）
- 飞书客户端移植完成（respx 模拟单测）
- 数据源前置动作：飞书企业自建应用已申请；内外部业务数据平台 API 清单盘点完成（写入 docs/11）

退出标准（全部满足才进阶段1）：

2. `/api/v1/health/deps` 全通（PG/Redis/MinIO/LLM）

## 阶段1：权限 + 知识库 MVP（2 周）

核心目标：登录可用、知识库可用——管理层从此可以把公司文档丢进系统并检索问答。

交付物：

- 登录认证 + 3 角色权限（admin / executive / member），表结构预留四级 RBAC 扩展位
- 文档上传（MinIO）→ 分块 → 向量化（pgvector）→ 语义检索 → 回答带来源溯源
- Embedding A/B 选型：通义 embedding vs bge-m3，用真实公司文档对比检索质量后定型
- `llm_call_log` 入库（模型用量从日志升级为数据库记录）

验收标准：权限拦截有效；上传一批真实文档后检索问答准确且可溯源到原文片段。

阶段价值：一个可用的"企业知识库问答系统"。

## 阶段2：平台运营部智能体闭环（3~4 周）

核心目标：落地首个部门智能体的完整业务闭环，验证自动化价值。

交付物：

- 数据接入按确定性递减顺序推进：**Excel/文档人工上传 →内外部业务数据平台 API → 飞书数据**（先做最可控的，API/飞书遇阻不阻塞主线）
- 业务时序数据入 TimescaleDB
- 平台运营部 AI 智能体：运营日报自动生成、指标异常告警、智能提案输出
- 前端 React + Ant Design Pro 初始化 + 运营看板
- 飞书通知推送启用（日报/告警推群）

验收标准：日常数据监控、日报生成、异常告警、提案输出全自动运行，管理层在看板和飞书中可直接消费。

阶段价值：运营部的日报和告警不再需要人写。

## 阶段3：任务卡 + 调度中枢（3 周）

核心目标：任务卡全流程流转 + 智能体调度中枢，验证多部门复制能力。

交付物：

- **前置 3 天 LangGraph 1.x POC**（此前禁止安装）：验证状态图编排任务卡流转可行性，POC 不通过则退回自研状态机
- 任务卡全流程：创建 → 拆解 → 分发 → 执行 → 汇报 → 验收闭环
- 智能体调度中枢（基于 LangGraph 1.x）
- 第二个部门 Agent 复制验证（复用平台运营部模板，验证"新增一个部门智能体"的边际成本）

验收标准：复杂任务可自动拆解、跨部门分发、闭环落地；第二部门 Agent 以显著低于首个的工作量上线。

## 阶段4：决策会商（2~3 周）

核心目标：提案评审 → 会议会商 → 决议落地的完整决策闭环。

交付物：

- 提案池管理（提案卡全生命周期）
- AI 会前预研报告（deepseek-reasoner 承担会商推理）
- 会中 AI 专家智能体参与讨论
- 自动会议纪要 + 决议转任务卡

验收标准：一场完整决策会议全流程跑通；**所有决议必须真人确认后才生效**（权责红线）。

## 阶段5：自进化 + 应急（2 周）

核心目标：让系统能被用户反馈驱动改进。原 4 周内容按价值排序，**优先做"反馈评分 → 提示词优化链"**，其余（流程自动复盘、异常应急体系、系统监控告警）按剩余时间裁剪，裁掉的转入 backlog。

交付物：

- AI 输出反馈评分机制 + 基于评分的提示词优化链路
- （按需）突发事件应急处理流程
- （按需）流程复盘与系统监控告警

验收标准：用户对 AI 输出的评分能实际驱动提示词迭代。

## 阶段6：服务器迁移部署（1 周）

核心目标：从开发机迁移到生产服务器，灰度上线。

交付物：生产环境部署（docker compose）、日志与监控、数据库备份策略、用户操作手册。

验收标准：管理层 3~10 人真实使用，系统 7 天稳定无故障。
