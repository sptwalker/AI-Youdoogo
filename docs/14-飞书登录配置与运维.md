# 14-飞书登录配置与运维

## 1. 范围与安全边界

本能力是 `ai.youdoogo.com` 应用自身的登录入口，不依赖统一登录门户，也不改变现有
用户名/密码、角色或资源授权语义。

- 飞书仅完成用户身份验证；系统只认当前应用范围内稳定的 `open_id`。
- 不按姓名、邮箱、手机号自动关联，不自动创建用户，不自动授予角色。
- 只有管理员预先创建、未删除、已启用且绑定对应 `open_id` 的用户可以进入。
- 使用飞书当前用户 OAuth：授权码 + PKCE → v3 `user_access_token` →
  `/open-apis/authen/v1/user_info`。不使用 tenant token 代表浏览器用户。
- 飞书 user access/refresh token 不落库；本实现不申请 `offline_access`。
- OAuth state 和应用 JWT 交接均存 Redis、短时有效、原子一次性消费。JWT 不进入重定向 URL。

## 2. 飞书开放平台必须手工完成的配置

在企业自建应用的「开发配置 → 安全设置 → 重定向 URL」中精确登记：

```text
https://ai.youdoogo.com/api/v1/auth/feishu/callback
```

不得添加 `/lodge/` 前缀，也不要登记前端 `/login` 地址。应用可用范围必须覆盖需要登录的
人员。

登录只读取 `/authen/v1/user_info` 返回的基础 `open_id`，该接口的基础用户信息没有额外
API 权限要求。因此登录流程不需要申请通讯录、邮箱、手机号或 `offline_access` scope。
现有消息、文档、多维表格能力所需权限与登录无关，继续按本项目原有飞书集成配置。

## 3. 环境与运行时配置

不填写真实值到仓库、工单或日志。单机 Compose 通过 `.env.production` 设置；CCE 将
`FEISHU_APP_ID` / `FEISHU_APP_SECRET` 放入现有 Runtime Secret，将
`FEISHU_OAUTH_ENABLED` / `FEISHU_REDIRECT_URL` 放入现有 Runtime ConfigMap。也可在密码登录后
通过管理员「系统配置 → 飞书」按现有 runtime config 规则设置：

```text
FEISHU_APP_ID=<企业自建应用 App ID>
FEISHU_APP_SECRET=<企业自建应用 App Secret>
FEISHU_REDIRECT_URL=https://ai.youdoogo.com/api/v1/auth/feishu/callback
FEISHU_OAUTH_ENABLED=true
```

`FEISHU_REDIRECT_URL` 不是密钥。生产环境只接受上面的精确 HTTPS 地址；配置缺失、开关关闭、
Redis 不可用或地址不安全时，仅飞书登录端点 fail closed，不阻断应用启动和密码登录。

GitLab `ai` 组中同名的 `FEISHU_APP_ID` / `FEISHU_APP_SECRET` 是流水线通知凭证，不会自动
注入 CCE 应用 Pod；启用登录时必须单独完成上述 backend 运行时配置。

## 4. 用户预建与绑定

1. 管理员先在「系统管理 → 用户与权限」创建用户并配置原有角色/部门/资源授权。
2. 从**同一个飞书应用**的可信管理员流程取得目标用户 app-scoped `open_id`；不得用显示名、
   邮箱或手机号代替，也不要使用其他飞书应用的 `open_id`。
3. 在用户行选择「绑定 / 更新」，填写 `open_id`。一个 `open_id` 只能绑定一个系统用户。
4. 用户再点击登录页「飞书登录」。未知、未绑定、已删除或停用用户收到相同的非枚举提示。

解绑只阻止后续飞书登录。由于本项目现有 JWT 是无状态令牌，如需立即收回已登录用户访问，
应沿用现有做法同时停用用户；每次受保护请求都会实时检查停用/删除状态。

## 5. 回滚与停用

- 紧急停用：将 `FEISHU_OAUTH_ENABLED=false`（或系统配置中的飞书登录开关关闭）。密码登录不受影响。
- 代码回滚：先关闭开关，再回滚应用；数据库列可保留。确需回退迁移时先备份，再执行
  `alembic downgrade 018_ui_secrets`，这会删除 `feishu_open_id` 绑定与两个非密配置项。
- 不需要撤销现有角色或资源授权；它们与登录方式独立。

- `uv run mypy app`
- `uv run pytest -q`
- `uv run alembic upgrade head --sql`（需使用 PostgreSQL URL）
- `cd frontend && npm run lint && npm run build`
- `git diff --check`

离线测试覆盖 state 过期/重放/篡改、外部 return-to 拒绝、未知/未绑定/停用用户、飞书 v3
user-token 调用、一次性交换及重定向 URL 不含应用 JWT。真实飞书授权与生产域名 TLS/反向代理
只能在完成第 2 节人工配置后做受控验收。CCE 的 ELB/Ingress 还必须由平台负责人确认不会把
该回调的 query string 写入上游访问日志；应用 frontend Nginx 与 Uvicorn 已分别关闭/清除。
