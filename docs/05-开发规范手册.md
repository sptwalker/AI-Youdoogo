# 05-开发规范手册

> 提取自原前置开发文档"05-项目开发规范手册"，按 2026-07-11 修订决策更新。技术栈唯一事实源为项目根目录 `CLAUDE.md`。

## 1. 项目目录规范

严格遵循统一目录结构，禁止随意新增文件夹、随意放置代码。新增一级目录须先修订本文档。

```text
├── app/                    # 后端主应用
│   ├── api/                # 接口层（薄，只做路由+校验+调service，版本化 api/v1/）
│   ├── core/               # 核心配置、鉴权、异常、日志、数据库连接
│   ├── models/             # 数据库模型（base.py 通用字段Mixin）
│   ├── schemas/            # 数据校验模型（Pydantic v2）
│   ├── services/           # 业务逻辑层
│   ├── agents/             # 智能体核心逻辑（阶段2起）
│   ├── knowledge/          # 知识库模块（阶段1起）
│   ├── llm/                # 多模型网关（factory/fallback/health/validate/roles）
│   ├── integrations/       # 外部平台集成
│   │   └── feishu/         # 飞书异步 httpx 客户端（不用 lark-oapi SDK）
│   └── utils/              # 通用工具
├── frontend/               # 前端项目（React + Ant Design Pro，阶段2才初始化）
├── docs/                   # 所有项目文档
├── tests/                  # 单元测试
├── scripts/                # 冒烟脚本
├── docker/                 # 容器配置
├── pyproject.toml          # 依赖管理（uv 管理：uv sync / uv run）
└── docker-compose.yml      # 本地编排
```

补充约束：目录/表/服务只在当前阶段用到时创建，禁止为未来阶段预建空壳。

## 2. 代码开发规范

- 严格遵循PEP8编码规范，使用Ruff自动格式化、代码检查
- 全代码层Mypy类型注解，无任何类型缺失
- 所有函数、类、接口必须编写标准文档字符串
- 核心业务逻辑必须添加注释，说明设计思路与边界条件
- 禁止硬编码密钥、地址、配置，统一读取环境变量（`.env` → `app/core/config.py` 唯一配置入口）
- 数据库操作统一使用ORM（SQLAlchemy 2.0 async），禁止原生SQL拼接
- 提交前质量门三件套必须全绿：`uv run ruff check .` + `uv run mypy app` + `uv run pytest`

## 3. Git协作规范

### 3.1 分支规范

- main：生产稳定分支，禁止直接提交代码
- dev：开发主分支，所有功能合并至此处
- feature/xxx：新功能开发分支
- fix/xxx：bug修复分支

### 3.2 提交规范

遵循Conventional Commits：feat/fix/docs/refactor/test/chore + 描述

## 4. AI开发专属规范（Claude Code专用）

- 文档优先：所有开发必须基于docs正式文档，禁止自由扩展功能
- 增量开发：单次仅开发一个独立模块，完成验收再继续下一模块
- 测试同步：核心代码必须同步编写单元测试，通过率100%
- 人工兜底：权限、数据修改、核心决策代码必须人工审核
- 幻觉校验：所有第三方调用、SQL、模型逻辑必须人工核验

## 5. 接口开发规范

- 统一RESTful风格接口命名
- 所有接口统一返回格式，包含code、msg、data
- 所有接口必须添加权限校验、参数校验
- 接口自动生成OpenAPI文档，可在线查看

## 6. 安全开发规范

- 最小权限原则，禁止超范围数据访问
- 所有外部输入参数校验、防注入、防越权
- 敏感数据传输加密、存储加密
- 所有操作全链路日志留存，可追溯
