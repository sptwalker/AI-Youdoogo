## 二、红线矩阵核验（§四，逐行守住）

| 场景 | 处置 | 证据 |
|---|---|---|
| 自动沉淀写个人库 | 走 `knowledge_index`（AUTOMATIC）内部辅助执行不外发 | `policies.py` `knowledge_index ∈ AUTOMATIC_CAPABILITIES` → `requires_human_review` 恒 False |
| 智能排程 | 建议态 suggested，真人 confirm 才生效 | `domain/models.py` `create_suggested`/`confirm`；`use_cases.py` `confirm_schedule` 经 owner 校验 |
| 番茄钟拦截 | 仅跳过发给本人的通知，不改对外红线 | `operations.py` 仅 `session and recipient_user_id` 且本人专注期才跳过；对外两处调用不传 recipient |
| 会后待办 | 建草稿 Task，真人可编辑/驳回，不自动对外 | `convert_resolution` 要求决议 `is_confirmed`；`confirm_resolution` 强制 `ConfirmationActorType.HUMAN` |
| 会前推送（对外） | 必停 `waiting_human` | `pre_meeting_reminder.py` 对外经 `requires_human_review` → `stopped=True` 不直发不建卡 |
| 个人数据 | 全 owner_id 隔离，命中他人 → `ResourceNotFound` | time_management `_load_schedule/_end_focus`；my_knowledge owner 恒登录用户；schedule 路由 owner=user.id |

行级隔离专项：知识/日程/专注·时间三条个人数据路径读写全部以登录用户 owner 过滤，跨人访问返回 404/`ResourceNotFound`，未见泄露路径。

## 四、已知完整性缺口（backlog，非红线偏离）

独立审查发现两条**非阻断**完整性观察，均为 docs/27-B 已用 `# ponytail:` 显式延后项：

1. **（中）B2 部分用例未挂 HTTP 路由，番茄钟拦截线上暂不可触发。** `app/api/v1/schedule.py` 仅暴露 `GET /schedules` 与 `POST /schedules/{id}/confirm`（B4 视图所需）；`start/complete/abort_focus`、`suggest_schedules`、`weekly_review`、`log_time` 仅有 `entrypoints/operations.py` 函数。连带全仓无调用向 `send_to_recipient` 传 `recipient_user_id`，故 B2.3 单点拦截虽实现正确且有单测，线上暂不触发（默认不拦截 = 安全，无红线风险）。
   - 上线接线时补 focus/weekly/suggest 路由，并让自我通知路径传入 `recipient_user_id`；对应 `schedule.py` 顶部 ponytail 注记。
2. **（低）B1.3 自动沉淀默认关闭**（`config.py` `personal_knowledge_autosink_enabled=False`）。特性门控避免噪声；内测前按需开启。
3. **（低）B2.3 拦截 best-effort、无补发队列**（代码已 ponytail 注明），符合清单预期，仅备案。

未发现：红线绕过、跨人数据泄露、多 migration head、import 环回归。
