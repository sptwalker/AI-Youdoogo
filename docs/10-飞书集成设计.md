# 10 - 飞书集成设计

> 版本：v1.0（2026-07-11）
> 定位：本项目飞书能力的唯一设计文档。飞书是本系统首要的消息触达与数据接入渠道（数据源三类之一，另见 docs/11-数据接入设计）。
> 技术栈以 CLAUDE.md 为唯一事实源：自研异步 httpx 客户端，**不使用 lark-oapi SDK**。

## 1. 复用来源与落位

### 1.1 复用来源

复用 `feishu_project_manager` 项目 backend 的 `FeishuClient`（源文件：`feishu_project_manager/backend/core/feishu.py`）。该客户端为纯异步 httpx 实现，已在生产环境稳定运行，无第三方 SDK 依赖（仅 httpx，本项目已有）。

### 1.2 本项目落位

```
app/integrations/feishu/
├── __init__.py      # 导出 feishu_client 单例
├── client.py        # FeishuClient：tenant token/消息/docx/bitable（移植主体）
├── oauth.py         # 用户 OAuth：授权 URL/code 换 user_access_token/取 open_id
├── cards.py         # 交互卡片模板构造（纯函数，产出 card dict）
└── notify.py        # 业务通知门面：全局开关 + best-effort 封装
```

调用规则：**业务代码（services 层）只调 `notify.py` 或 `client.py` 的公开方法**，不直接拼飞书 API 请求；卡片 JSON 统一在 `cards.py` 构造，避免散落。

## 2. 已有能力清单（移植即得）

| 能力 | 方法 | 说明 |
|---|---|---|
| tenant_access_token 缓存 | `get_tenant_access_token()` | 内存缓存，**提前 60 秒过期**避免边界失效；缓存按凭证 key（app_id+secret）失效 |
| 发送消息（通用） | `send_message(receive_id, msg_type, content, receive_id_type)` | `receive_id_type` 支持 `user_id` / `open_id` / `chat_id` |
| 发送文本 | `send_text(receive_id, text, receive_id_type)` | 包装 `msg_type=text` |
| 发送交互卡片 | `send_card(receive_id, card, receive_id_type)` | 包装 `msg_type=interactive` |
| 创建云文档 | `create_document(title)` | docx v1，返回 `document_id` |
| 追加文档块 | `append_document_blocks(document_id, blocks)` | **50 块/批** 分批顺序追加 + 批间 0.4s 限速（飞书限制：单次≤50 子块、每秒≤3 次） |
| 块构造工具 | `text_block` / `rich_block` / `heading_block` | 静态方法，构造段落/富文本/标题块 |
| 多维表格 | `bitable_list_records` / `bitable_create_record` / `bitable_update_record` | list 支持 `filter` 表达式与 `page_size` |
| OAuth 登录 | `FeishuOAuthClient.authorization_url` / `identity_from_code` | 独立于 tenant-token client；服务端通过 `https://open.feishu.cn/open-apis/authen/v2/oauth/token` 换取 user_access_token，仅用于当次取 open_id，不落库 |
| 统一错误 | `FeishuAPIError` / `FeishuAuthError` | HTTP 错误与业务 code!=0 均转为异常 |

## 3. 本项目改造点

移植不是原样复制，须做以下三处改造：

1. **配置读取改造**：原实现 `from backend.core.config import get_settings` → 改为读本项目 `app/core/config.py`（pydantic-settings 唯一配置入口）。新增配置项：
   ```
   FEISHU_APP_ID=
   FEISHU_APP_SECRET=
   FEISHU_OAUTH_ENABLED=false    # 登录开关，未完整配置时端点 fail closed
   FEISHU_REDIRECT_URL=          # OAuth 回调；生产值见 docs/14
   FEISHU_NOTIFY_ENABLED=false   # 通知全局开关，默认关闭
   ```
2. **删除 DB 凭证分支**：原实现凭证解析链为 `override > DB系统设置表 > env`。本项目**凭证只走环境变量**（开发铁律第4条），删除 `_db_credentials()` 及 override setter 逻辑，`_creds()` 直接返回 settings 值；token 缓存的按凭证 key 失效逻辑随之简化（凭证进程内不变）。
3. **新增 notify.py 通知门面**，三条设计约束：
   - **全局开关**：`FEISHU_NOTIFY_ENABLED=false` 时所有通知函数直接返回，不发请求（开发/测试环境默认关闭，避免误打扰）；
   - **best-effort**：通知失败**只记 WARNING 日志，不抛异常、不阻断主业务流程**（会商结论已落库，飞书推送失败不能让决策流程报错）；
   - **纯值入参**：通知函数只接收字符串/字典等纯值（如 `notify_meeting_result(user_id: str, title: str, summary: str)`），**不接收 ORM 对象**，避免 session 生命周期问题与模块耦合。

## 4. 阶段应用场景

| 阶段 | 场景 | 用到的能力 |
|---|---|---|
| 阶段1 | 无（仅完成客户端移植 + 单测） | token/send_text 冒烟 |
| 生产登录 | 飞书用户 OAuth 登录；OAuth 成功后按 open_id 自动开户或复用有效用户 | oauth.py + Redis 一次性 state/exchange |
| 阶段2 | 任务卡/日报通知推送管理层；飞书多维表格数据接入 | send_card、bitable_list（需补分页） |
| 阶段3+ | 会商结论卡片推送、会商纪要写入云文档 | send_card、create_document + append_blocks |

## 6. 前置条件：飞书企业自建应用申请

开发前需在飞书开放平台创建**企业自建应用**，获取 `app_id` / `app_secret`（写入 `.env`，禁止入库、禁止硬编码），并开通以下权限 scope：

| scope | 用途 |
|---|---|
| `im:message`（发送消息） | 文本/卡片通知推送 |
| `docx:document`（云文档读写） | 会商纪要文档创建与写入 |
| `bitable:app`（多维表格读写） | 多维表格数据接入与回写 |

另需：应用可用范围覆盖首批用户（管理层 3~10 人）；若启用 OAuth 登录，按
`docs/14-飞书登录配置与运维.md` 配置精确重定向 URL。登录本身不申请通讯录、邮箱、
手机号或 `offline_access`；`/authen/v1/user_info` 的基础 `open_id` 无额外 API 权限要求。
若启用 webhook 事件订阅（阶段2按需），配置事件回调地址与 encrypt_key。

## 7. 验收标准（客户端移植模块）

1. `uv run pytest`：token 缓存（含提前过期）、send_text/send_card、append_blocks 分批逻辑有单测（httpx 打桩，不打真实 API）；
2. `FEISHU_NOTIFY_ENABLED=false` 时 notify 函数零网络请求；`=true` 且 API 失败时仅产生 WARNING 日志、调用方无异常；
3. Ruff + Mypy 全绿，全类型注解。
