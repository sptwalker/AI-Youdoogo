# 12-生产部署与运维手册

> 阶段6 交付。面向单台 Linux 生产服务器 + Docker Compose 部署。技术栈唯一事实源见项目根 `CLAUDE.md`。

## 1. 架构与镜像

```
                 :80
用户浏览器 ──► Nginx(frontend 镜像) ──┬─ 静态 SPA(React 构建产物)
                                     └─ /api/ 反代 ─► backend(uvicorn 多worker)
                                                        │
                                          ┌─────────────┼─────────────┐
                                     postgres(pgvector) redis        minio
```

- `Dockerfile`：后端镜像（uv 装依赖 → 启动先 `alembic upgrade head` 再多 worker 起 Uvicorn）
- `frontend/Dockerfile`：前端镜像（node 构建 → nginx 托管静态 + 反代 `/api`）
- `docker-compose.prod.yml`：5 服务编排，仅 Nginx 暴露 `:80`，PG/Redis/MinIO 内网不 publish
- `docker/nginx/nginx.conf`：SPA 回退 + `/api` 运行时 DNS 解析反代（避免 backend 未就绪时 nginx 起不来）

## 2. 首次部署（生产服务器）

前置：Linux + Docker Engine + Docker Compose v2；已放通 80 端口。

```bash
git clone <repo> /opt/youdoo && cd /opt/youdoo
git checkout main                                  # 用打了 tag 的稳定分支

cp .env.production.example .env.production
#   必填：POSTGRES_PASSWORD / MINIO_ACCESS_KEY / MINIO_SECRET_KEY
#   DATABASE_URL 里的密码手填为 POSTGRES_PASSWORD 的实际值
#   JWT_SECRET：python -c "import secrets;print(secrets.token_urlsafe(48))"
#   大模型密钥：DEEPSEEK_API_KEY / DASHSCOPE_API_KEY(含 embedding) / ZHIPU_API_KEY
vim .env.production

docker compose --env-file .env.production -f docker-compose.prod.yml up -d --build
#   backend 启动时自动跑迁移（全套 alembic upgrade head，含种子运营AI总监/会商AI专家、
#   数据接口/事件别名/语义术语等），并在库中无卡片且填了 DEEPSEEK_API_KEY 时自动种
#   2 张 AI 卡片（daily/reasoning），开箱即 AI 可用。

# 建首个管理员（交互式输入密码）
docker compose -f docker-compose.prod.yml exec backend \
  python scripts/create_admin.py admin 管理员

# 自检
curl -s http://localhost/api/v1/health/deps          # 期望 postgres/redis/minio 全 ok
```

浏览器打开 `http://<服务器IP>/` → 用管理员账号登录。

> **AI 卡片**：若首启未填 `DEEPSEEK_API_KEY`（或想用别的模型），登录后到「AI 配置」页
> 手动建 daily + reasoning 卡片——**无卡片时 AI 不可用**（不回退 .env，见 CLAUDE.md 技术栈）。
> Embedding / Rerank / 飞书 / ThinkingData 等密钥在「系统配置」页填（存 sys_config，脱敏）。

## 3. 升级与回滚

```bash
# 升级
cd /opt/youdoo && git pull && git checkout <新tag>
docker compose --env-file .env.production -f docker-compose.prod.yml up -d --build
#   迁移随 backend 启动自动执行；升级前务必先备份（见 §4）

# 回滚（代码）
git checkout <上一个稳定tag> && docker compose ... up -d --build
# 回滚（数据）：见 §4 从 pg 备份恢复
```

> 迁移不可逆变更（删列/改类型）上线前必须先备份；Alembic 迁移均带 downgrade，可 `alembic downgrade -1` 回退一步。

## 4. 数据备份与恢复（docs/08 §3.2）

- 脚本 `scripts/backup.sh`：PG 全量 `pg_dump` + MinIO 对象镜像，保留近 30 天。
- 定时（crontab）：
  ```
  0 3 * * * cd /opt/youdoo && sh scripts/backup.sh >> /var/log/youdoo-backup.log 2>&1
  ```
- 恢复 PG：
  ```bash
  gunzip -c backups/pg/youdoo_YYYYmmdd_HHMMSS.sql.gz | \
    docker compose -f docker-compose.prod.yml exec -T postgres psql -U postgres -d youdoo
  ```

## 5. 日志与监控（docs/08 §3.3）

- 日志走 stdout，Docker `json-file` 驱动 + 轮转（compose 已配 `max-size=20m max-file=5`）：`docker compose -f docker-compose.prod.yml logs -f backend`
- 存活/依赖探针：`GET /api/v1/health`、`GET /api/v1/health/deps`（PG/Redis/MinIO 逐项）——可接入外部监控定时探测
- 大模型：调用成败/耗时/降级写结构化日志；用量入 `llm_call_log`，当日超 `LLM_DAILY_TOKEN_BUDGET` 告警并（开启时）推飞书运营群
- 迭代运维：每两周复盘，按反馈评分优化智能体提示词（智能体页「优化提示词」）

> 已知约束：熔断器与 LLM 健康态为**每-worker 内存态**（docs/09 §3.5），多 worker 下各自独立；单机小规模可接受，需全局一致时改 Redis 计数。

## 6. 用户操作手册（管理层）

登录后左侧菜单分模块：

| 模块 | 用途 | 关键操作 |
|---|---|---|
| **工作台** | 概览入口 | — |
| **知识库** | 公司文档问答（带来源溯源） | 上传 txt/md/docx/pdf 或粘贴/飞书文档入库 → 提问，答案标注来源片段 |
| **运营看板** | 平台运营数据 + AI 日报/告警 | 上传运营日数据 Excel → 选日期「生成运营日报」/「异常检测」 |
| **智能体** | 角色管理 + 留痕 + 自进化 | 查看执行留痕、对产出 1~5 星评分；角色卡「优化提示词」基于低分反馈生成改进版（**真人确认后应用**） |
| **任务卡** | 任务全流程 | 新建/指派智能体 → 「运行」调度执行 → 「验收/驳回」（**验收须真人**） |
| **提案** | 运营/决策提案闭环 | 新建 → 「AI预研」→ 「评审」通过/驳回（**真人**）→ 「转任务卡」 |
| **会议会商** | 决策会议 | 新建 → 开始 → 发言/「AI专家」→ 投票/「AI参考票」+ 统计票型 → 「生成纪要」→ 登记决议 → **确认生效**（真人）→ 转任务卡 |
| **用户管理** | 账号（仅管理员） | 新建/停用/改角色（admin/executive/member） |

**权责红线（全程强制）**：AI 仅有建议/分析/辅助执行权；任务验收、提案通过、决议生效、提示词应用等一切生效动作均须真人确认——AI 不能自行落地涉及业务/资金/项目/人事的决议。
