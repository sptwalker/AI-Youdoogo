【开发任务：智能工作收件箱 + 多项目管理看板】

步骤1：收件箱聚合服务（app/workspace/services/inbox_service.py）
- 实现多源待办聚合接口，首期接入：
  a) 已有系统的任务卡分配（通过已有 TaskCardService）
  b) 飞书消息中的 @提及与待办（调用已有飞书集成模块）
  c) 系统内部的审批待办（调用已有审批服务）
  d) AI任务完成通知
- 实现 InboxItem 的自动分类与去重逻辑
- 实现优先级打分算法：
  score = 0.4*截止时间紧迫度 + 0.25*影响范围 + 0.2*上级关注度 + 0.15*紧急程度
  每个因子需有明确的计算函数
- 实现 AI 摘要生成：对每条收件箱事项调用大模型生成一句话摘要与处理建议
- 实现批量处理接口：支持批量标记已读、批量归档、批量转任务

步骤2：收件箱 API（app/workspace/api/inbox.py）
- GET /inbox — 分页查询收件箱，支持按类型/状态/优先级筛选，默认按 priority_score 降序
- GET /inbox/stats — 获取收件箱统计（未读数、各类型数量、高优数量）
- POST /inbox/{id}/process — 处理单条事项（转任务/委派/归档/标记已读）
- POST /inbox/batch-process — 批量处理
- POST /inbox/refresh — 手动触发待办刷新

步骤3：任务看板服务（app/workspace/services/task_service.py）
- 实现任务 CRUD，支持批量更新状态
- 实现任务进度自动追踪：
  a) 每日定时任务（用已有 Celery/APScheduler）扫描关联数据
  b) 根据关联文档更新、AI任务进度、子任务完成情况自动计算进度
  c) 进度偏差超过20%时生成预警（写入收件箱）
- 实现阻塞检测：任务状态为 in_progress 但超过48小时无更新，自动标记为 blocked
- 实现依赖关系管理：添加/移除依赖，前置任务状态变更时联动检查
- 实现延期影响分析：某任务延期时，递归计算对下游任务的影响

步骤4：任务看板 API（app/workspace/api/tasks.py）
- GET /tasks — 多条件筛选查询（项目/状态/优先级/负责人/时间范围）
- POST /tasks — 创建任务
- PUT /tasks/{id} — 更新任务
- PATCH /tasks/{id}/status — 快速变更状态
- GET /tasks/{id}/detail — 任务详情（含上下文、子任务、依赖、活动日志）
- POST /tasks/{id}/subtasks — 创建子任务
- POST /tasks/{id}/dependencies — 添加依赖关系
- GET /tasks/kanban — 看板视图数据（按状态分组）
- GET /tasks/timeline — 时间线视图数据（甘特图格式）
- GET /tasks/calendar — 日历视图数据

步骤5：前端页面开发
- frontend/src/pages/workspace/inbox/ — 收件箱页面
  - 左侧分类筛选栏，中间事项列表，右侧详情抽屉
  - 支持批量选择与操作
  - 优先级用颜色标签区分
- frontend/src/pages/workspace/kanban/ — 任务看板页面
  - 看板视图：拖拽式列布局，任务卡片展示关键信息
  - 时间线视图：基于 gantt-task-react 或类似库实现
  - 任务详情抽屉：展示完整上下文、活动日志、子任务、依赖
  - 顶部筛选栏：按项目、负责人、优先级筛选

【验收要求】
- 收件箱能正确聚合至少3个来源的待办，去重逻辑有效
- 优先级排序结果合理，可通过人工反馈调整权重
- 任务看板支持拖拽变更状态，实时保存
- 四种视图数据接口返回格式正确
- 阻塞检测与延期影响分析逻辑正确，有单元测试覆盖
- 前端页面响应式，加载时间≤2秒
