【开发前必读规范重申】

1. 每次开发前，先执行以下动作：
   - git pull 拉取最新代码
   - 阅读本次涉及的已有模块代码，理解现有实现
   - 说明本次开发的文件清单与实现思路，等待确认

2. 代码生成后必须自动执行：
   - ruff check --fix 修复代码风格
   - mypy 类型检查，修复所有错误
   - pytest 运行相关测试，确保全部通过
   - 生成的新代码必须有对应单元测试

3. 数据库变更必须：
   - 生成 Alembic 迁移脚本
   - 在测试环境执行迁移验证
   - 迁移脚本需支持回滚

4. 前端开发必须：
   - 复用已有组件，不重复造轮子
   - 遵循已有代码风格与目录规范
   - 接口调用使用已有 request 封装
   - 状态管理使用已有方案（Redux/Zustand 等）

5. 涉及以下内容必须标注「需人工审核」：
   - 权限控制与数据安全相关代码
   - 核心业务逻辑与算法
   - 外部API调用与数据修改
   - 大模型Prompt的重大变更

6. 每个功能点开发完成后，输出：
   - 涉及的文件清单
   - 实现的功能说明
   - 测试结果
   - 待人工审核的关键点
