【开发任务：子系统基础脚手架与数据模型】

步骤1：创建子系统目录结构
- 在 app/workspace/ 下创建 api/、models/、schemas/、services/、agents/、utils/ 目录
- 在每个目录下创建 __init__.py
- 在 app/workspace/__init__.py 中写模块说明

步骤2：设计并创建核心数据模型（app/workspace/models/）
创建以下 ORM 模型，继承已有 BaseModel（含 id、created_at、updated_at、is_deleted）：

1. WorkspaceProject（项目表）
   - name: str, 项目名称
   - description: str, 项目描述
   - owner_id: int, 负责人（关联已有用户表）
   - status: enum, 状态（active/archived/completed）
   - color: str, 看板颜色标记
   - sort_order: int, 排序权重

2. WorkspaceTask（任务卡表，统一任务抽象层）
   - title: str, 任务标题
   - description: text, 任务描述
   - project_id: int, 关联项目（可空）
   - owner_id: int, 负责人
   - creator_id: int, 创建人
   - status: enum, 状态（pending/in_progress/blocked/review/done/archived）
   - priority: enum, 优先级（low/medium/high/urgent）
   - due_date: datetime, 截止时间（可空）
   - estimated_hours: float, 预估耗时
   - actual_hours: float, 实际耗时
   - progress: int, 进度百分比 0-100
   - task_type: enum, 类型（ai_task/human_task/meeting_todo/system_alert/manual）
   - source: str, 来源（feishu/email/system/ai/manual等）
   - source_ref: str, 来源系统引用ID
   - parent_task_id: int, 父任务ID（支持子任务）
   - context_metadata: json, 上下文关联信息（对话ID、文档ID、决议ID等）

3. WorkspaceTaskDependency（任务依赖表）
   - task_id: int, 当前任务
   - depends_on_task_id: int, 依赖的前置任务
   - dependency_type: enum, 依赖类型（finish_to_start/start_to_start）

4. WorkspaceInboxItem（收件箱事项表）
   - user_id: int, 所属用户
   - task_id: int, 关联任务（可空）
   - item_type: enum, 类型（approval/reply/action/view/notification）
   - title: str, 标题
   - summary: str, AI生成的摘要
   - source: str, 来源渠道
   - source_ref: str, 来源引用
   - priority_score: float, AI计算的优先级分数
   - status: enum, 状态（unread/read/processed/archived）
   - ai_suggestion: text, AI建议的处理方式
   - metadata: json, 扩展字段

5. WorkspaceAITask（AI任务扩展表）
   - task_id: int, 关联 WorkspaceTask
   - execution_plan: json, AI拆解的执行计划（步骤列表）
   - current_step: int, 当前执行步骤索引
   - execution_log: json, 执行日志（每步的状态、耗时、结果摘要）
   - output_ref: str, 产出物引用（文档ID/文件路径）
   - output_version: int, 当前输出版本
   - quality_score: int, 质量评分 1-5
   - feedback: text, 用户反馈
   - model_used: str, 使用的模型
   - token_usage: int, Token消耗

步骤3：生成 Alembic 迁移脚本
- 使用已有 Alembic 配置生成迁移文件
- 为常用查询字段添加索引（owner_id+status, project_id, due_date, priority_score）

步骤4：创建 Pydantic Schemas（app/workspace/schemas/）
- 为每个模型创建 Create、Update、Response 三个 Schema
- Response Schema 需包含关联信息（项目名、负责人名等）

步骤5：注册路由
- 在 app/workspace/api/ 下创建 __init__.py 和 router.py
- 在主应用中挂载 /api/v1/workspace/ 路由前缀

【验收要求】
- 所有模型通过 Mypy 类型检查
- 生成并执行 Alembic 迁移，表结构正确
- 每个模型有对应的 Schema
- 路由可正常访问健康检查接口
- 生成模型与 Schema 的单元测试
