## 二、逐项落地说明

### A1 · project_management Context（个人项目聚合）
- 新叶子 Context `app/contexts/business/project_management/`，拥有 `Project` 模型（迁移 `046_project`）。
- **行级隔离是第一性约束**：`use_cases._load` 对 `get/update/archive` 统一 `owner_id != owner → ResourceNotFound`（命中他人不泄露存在性，返 404）；`list` 走 `list_for_owner(owner_id)` 只列本人。
- 入口 `api/v1/projects.py` 的 `owner_id` 一律取登录用户，拒绝客户端传入归属。

### A2 · 任务卡挂 project_id + archived_at
- task 增 `project_id`（可空外键）+ `archived_at`（软归档标记），迁移 `047_task_project_archive`。
- 创建任务挂 `project_id` 时经 `project_management.get_project(..., owner_id=creator_id)` 校验归属——挂他人项目 → 404，堵住越权关联。

### A3 · 看板泳道 + blocked 派生
- 泳道与 `blocked` 均为**派生只读投影**（由现有任务状态/依赖推导），不新增持久化字段、不新增 writer——符合「派生态不落库」与架构门禁「每模型单 writer」。

### A4 · 收件箱增强
- **优先级 4 因子打分** + **去重** + **已读/已处理态**（新 `InboxItemState`，迁移 `048`）+ **批量标记**。
- 隔离：`InboxItemState` 读写恒 `WHERE owner_user_id == principal.id`，owner 非客户端可控；admin 监督只读他人、写态仍锁本人（不串写）。
- 架构门禁：`InboxItemState` 仅由 `work_desktop` 一个 Context 写入（`test_migrated_orm_models_have_one_persistent_context_writer` 覆盖）。
- 红线：`mark_inbox` 只翻本人 `is_read/is_processed`，无来源改动、无对外发送分支；两字段皆空 → `RuleViolation`。**批量 = 真人确认读态，绝不触发自动对外**。

### A5 · 工作台前端外壳
- `pages/workspace/index.tsx` 以 `Segmented` 切换 看板 / 列表 / 收件箱（时间线/日历按规划延后至阶段 B）。

### A6 · AI 任务「先出计划再执行」
- **不新建引擎/表**，复用 `work_planning` + `workflow_runtime`：
  - `POST /ai-tasks/plan`：仅跑 `plan_work` 出 DAG 预览，**不落库、不执行**，供真人确认。
  - `POST /ai-tasks/execute`：用真人已确认、客户端回传的步骤重建 `WorkflowPlan`，`__post_init__` 在**信任边界复校** DAG（无环/依赖合法），非法 → `RuleViolation`(400)；`creator_id` 服务端锁定登录用户，**禁止客户端冒充**。
- 红线停点由 `workflow_runtime` 逐步判定强制（本入口不绕过、不放宽）；前端 `AiTaskView` 仅呈现与触发——红线步预览即标红、执行后停 `awaiting_human` 等真人「验收并继续」。

## 三、阶段级独立验收（对照 docs/27 §八 + §十一）

由独立验收员对两条最高风险线逐项取证：

**风险线 1 · 红线守住 —— 判定「守住」**
- `/plan` 全程无持久化/执行；`/execute` `creator_id=user.id` 服务端锁定、DAG 信任边界复校。
- 红线判定唯一事实源 = `workflow_runtime/domain/policies.py`（建步盖 `red_line` 戳）；`step_completion` 对红线步即使 `succeeded` 也强制转 `STEP_WAITING_HUMAN`，机械兜底真人停点。
- 收件箱批量仅翻本人读态、不外发。
- `test_ai_tasks_routes.py` 断言红线步执行后停 `STEP_WAITING_HUMAN` 并进 `awaiting_human`。

**风险线 2 · 行级隔离 —— 判定「守住」**
- project_management 全按 `owner_id`，命中他人 → `ResourceNotFound`；任务挂他人 project → 404。
- `InboxItemState` 按 owner 隔离、仅 work_desktop 写，admin 监督不串写。

**结论：两条风险线均有代码级强制 + 测试断言支撑，阶段 A 判通过。**

### 验收跟进项（已闭环）
验收指出维护性隐患：`work_planning.application.use_cases` 自留一份 `AUTOMATIC_CAPABILITIES`/`requires_human_review`，与 `workflow_runtime` 权威清单分叉（缺机械键等）。
- 核查确认该副本**零业务调用**（仅一处测试误引），属死代码。
- **处置（删除优于加注释）**：删掉 work_planning 的副本，`workflow_runtime/domain/policies.py` 成为唯一红线事实源；仅有的测试引用改指权威清单。
- 复跑全量 `1216 passed`，ruff/mypy 全绿——隐患消除，无功能回归。
