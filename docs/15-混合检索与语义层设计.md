# 15 · 混合检索与统一语义层设计

> 状态:已实现。混合召回、RRF、可选 rerank 与术语字典已由迁移 026~029 和对应 service/API 落地；本文保留设计依据与验收口径。
> 目标:①用"向量+关键词"多路召回 + RRF 融合(+分期 rerank)提升知识互通质量与准确度;
> ②建轻量统一语义层(指标/术语字典)降低跨部门理解与沟通成本。
> 红线不变:检索与语义层只有分析/辅助权,不新增任何生效权;部门可见范围隔离贯穿。

## 1. 背景与现状

**改造前现状(单臂向量检索)**:`retrieval.search()` 仅走 pgvector 余弦距离 + HNSW 索引,top_k=5,
经 `base._inject_knowledge` 注入每个 AI 提示词,按部门 `visible_kb_ids` 隔离；当前实现已升级为下文设计的混合检索链路。

**痛点**:单一向量擅长模糊语义,但对**专有名词/产品型号/精确编码**匹配极差(向量会把
"盒子A3" 和 "盒子A5" 拉得很近);而企业知识里恰恰充满这类精确词。且跨部门对同一概念
(指标名/维度)口径不一,AI 理解与沟通成本高。

**结论**:需在召回层加**关键词臂**做精确匹配,与向量臂融合;并建**统一语义层**统一口径。

## 2. 现有地基(复用,不重造)

| 能力 | 位置 | 复用方式 |
|---|---|---|
| 向量召回 + HNSW | `retrieval.search()` / `002_knowledge.py` | 作为混合检索的**向量臂**,不动 |
| embedding 客户端(外部端点模式) | `knowledge/embedding.py` | rerank 客户端复刻同款(端点+密钥+超时) |
| 检索注入全体 AI | `base._inject_knowledge` | 升级 `search()` 即全体 AI **透明受益**,零改调用方 |
| 部门范围隔离 | `retrieval.search(visible_kb_ids=…)` | 两臂都套同一 kb 范围,隔离不破 |
| 语义碎片 | `TdEventAlias`(事件码→中文)、`td_event_views`、Governed Data Query catalog operations | 语义层的血脉,泛化而非另起 |
| PG 扩展 | 已装 `vector` | 关键词臂加 `pg_trgm`(contrib 自带,免改镜像) |

## 3. 缺失地基(本设计新增)

1. **关键词召回臂** —— 无 pg_trgm、无 tsvector,精确词全靠向量瞎猜。
2. **多路融合** —— 无 RRF/加权合并,多臂结果无法统一排序。
3. **重排序** —— 无 rerank,融合后 top_k 未经精排。
4. **统一语义层** —— 无术语/指标字典,口径散在各处(TdEventAlias 仅事件码一类)。

## 4. 设计方案(分两阶段)

### 4.1 混合检索(阶段 A · 先做)

**关键词臂 = pg_trgm 三元组相似度**(决策1):
- 迁移建 `CREATE EXTENSION IF NOT EXISTS pg_trgm` + `knowledge_vector.chunk_text` 上
  `GIN (chunk_text gin_trgm_ops)` 索引。
- 召回:`word_similarity(query, chunk_text)` 降序取 top_n,套同一 `visible_kb_ids` +
  未删除过滤。三元组对**产品型号/专名/错别字**强(正中痛点),CJK 按字符成组,无需中文分词。

**RRF 融合**(决策2 首版,无参稳健):
- 两臂各自产出**有序 chunk 列表**;融合分 `score(d) = Σ_i 1/(k + rank_i(d))`,k 默认 60。
- 纯 Python 函数 `rrf_fuse(ranked_lists, k)`,**不依赖 DB,可单测**。融合后取 top_k。
- 首版并行度:两臂 `asyncio.gather` 并发跑,互不阻塞。

**search() 透明升级**:
- 保持签名 `search(db, query, top_k, *, visible_kb_ids)` 不变,内部改为
  向量臂 + 关键词臂并发 → RRF 融合 → top_k。**调用方(base/answer)零改动**。
- 配置开关(sys_config,默认开):`retrieval_hybrid_enabled`(关则退回纯向量)、
  `retrieval_rrf_k`、`retrieval_candidate_n`(每臂候选数)。
- **优雅降级**:关键词臂异常/SQLite/无 pg_trgm → 该臂返回 [],自动退化为纯向量,不阻断。

**Rerank(阶段 A.2 · 分期挂 flag,决策2)**:
- 复刻 `embedding.py` 建 `rerank.py`(外部 cross-encoder 端点,如通义 gte-rerank / bge-reranker)。
- 位置:RRF 融合后的 top_n → rerank 精排 → 最终 top_k。
- 开关 `retrieval_rerank_enabled`(默认关);未配密钥/异常 → 跳过 rerank,用 RRF 结果,不阻断。

### 4.2 统一语义层(阶段 B · 后做,轻量字典,决策3)

**新表 `semantic_term`**(泛化 TdEventAlias,不做知识图谱):
- `canonical_name` 规范名(如"累计激活设备数")
- `aliases: JSONB` 别名/同义词列表(如 ["新增设备","激活量","new_device 用户"])
- `term_type` 类型:metric(指标)/ dimension(维度)/ entity(实体)
- `definition` 口径定义(一句话说清算法/边界)
- `linked_view` / `sql_template` 关联 TD 视图或取数模板(指标类)
- `kb_refs: JSONB` 关联知识库文档引用(概念类)
- 可选 `department_id` 归属范围

**两个用途**:
1. **提示词注入** —— 复刻 Governed Data Query `catalog_prompt` 思路,把术语字典渲成
   【业务术语】段注入 AI,统一跨部门口径(AI 一眼知道"激活量"= 规范"累计激活设备数"+ 其算法)。
2. **查询扩展** —— 检索前把 query 里命中的别名 → 规范名 + 同义词一并塞进**关键词臂**输入
   (向量臂不用扩,语义已覆盖),提升精确词召回。

**管理 UI**(前端):术语字典的增删改查页,admin 维护。指标类可一键从 TdEventAlias 导入。

## 5. 红线合规(贯穿)

- 检索/语义层只提供**参考资料 + 口径**,不新增任何"生效权";AI 输出仍可编辑/驳回/终止。
- 部门 `visible_kb_ids` 隔离对**两臂都生效**,机密减法隔离不破。
- rerank/embedding 密钥走既有覆盖层(sys_config/.env),list 脱敏,不硬编码。
- 语义层是口径字典,不触发任何业务决议;涉资金/人事/项目的决议仍走真人确认。

## 6. 分期与验收

**阶段 A(混合检索,先做)**
- 迁移 026:pg_trgm 扩展 + chunk_text GIN 三元组索引。
- `retrieval.py`:拆 `_vector_arm` / `_keyword_arm`;加 `rrf_fuse` 纯函数;`search()` 改并发融合。
- 配置开关 + 优雅降级(纯向量兜底)。
- rerank(A.2):`rerank.py` 客户端 + flag,融合后精排。
- 验收:含产品型号/专名的查询,混合检索能召回向量臂漏掉的精确匹配;关闭 flag 行为同旧版。
- 测试:`rrf_fuse` 纯单测(排名融合正确性)、关键词臂降级不阻断、search 融合去重、rerank flag 开关。

**阶段 B(统一语义层,后做)**
- 迁移 027:`semantic_term` 表 + 可选从 TdEventAlias 导入种子。
- `semantic_service`:字典 CRUD + `term_prompt()` 注入段 + `expand_query()` 查询扩展。
- 接检索:关键词臂输入前做别名扩展;接 base:注入【业务术语】段。
- 前端:术语字典管理页(admin)。
- 验收:AI 对同一指标跨部门口径一致;别名查询能命中规范文档;字典可维护。
- 测试:expand_query 别名→规范扩展、term_prompt 渲染、CRUD 与范围隔离。

## 7. 已定决策(评审确认)

1. **关键词臂 = pg_trgm 三元组**(contrib 自带免改镜像,强于产品型号/专名匹配;非真 BM25 但对内部 KB 足够)。
2. **Rerank = 分期**(首版先"向量+关键词双臂 + RRF 融合";rerank 作 A.2 挂 config flag,见效快、少依赖)。
3. **语义层 = 轻量指标/术语字典**(泛化 TdEventAlias,非知识图谱本体;务实增量直接可用)。
4. **顺序 = 先混合检索,后语义层**(检索是质量直接杠杆,升级 search() 全体 AI 透明受益;语义层随后叠加)。
